# SM-X900 revision 5: sensor evidence

Recorded 2026-10-04 on the DYDC tablet running kernel `7.2-r70` sources from
a postmarketOS console root filesystem on the microSD card. The X800 story,
which this follows, is in [docs/12](../../docs/12-sensors.md).

## Inventory

From the stock `/vendor/etc/sensors/config` files that name the Waipio MTP
platform, and the stock device tree:

| Function | Part | Reach | Stock description |
|---|---|---|---|
| Accelerometer, gyroscope | ST LSM6DSO | SLPI I3C instance 1, address 0x6b | `waipio_lsm6dso_0_0.json` |
| Magnetometer | AKM AK0991x | SLPI I2C instance 2, address 0x0c | `waipio_ak991x_3.json` for revision 3 and later |
| Ambient light, two | Sensortek STK31610 | SLPI I2C instances 4 and 5, address 0x48 | `waipio_stk31610_0.json`, `_1.json` |
| Hall, cover | switch | TLMM 169, active low | `hall_ic/hall`, event 0x15 |
| Hall, S Pen | switch | TLMM 23, active low | `hall_ic/hall_wacom`, event 0x1e |
| AP thermistor | NTC | pm8350 ADC channel 0x144 | `sec_ap_thermistor` |
| Wi-Fi thermistor | NTC | pm8350 ADC channel 0x14a | `sec_wf_thermistor` |

The light sensor differs from the X800's VEML3328, and there are two. The
hall switches, the volume-up key (pm8350 gpio6) and both thermistor channels
equal the inherited X800 description.

## SLPI

The stock `remoteproc-slpi` node holds one sensor rail, PM8350C L2C at 1.8 V.
The X800's second rail, L13C at 3.0 V, has no consumer in the X900 tree; it
is 1.8 V here and left alone.

`slpi.*` and `adsp.*` from the DYDC firmware package's `NON-HLOS.bin`
(SHA-256 of `slpi.mdt` `fb39dcf8...`, `adsp.mdt` `ddc05b8a...`) boot under
mainline: both remote processors reach `running` 0.5 s after
`qcom_q6v5_pas` loads.

Alpine's `hexagonrpcd` 0.4.0 with no sensor tree is worse than no daemon.
The sensor process faults and the hub restarts every 4 s:

```
PDM: service 'sensor_process' crash: 'EF:sensor_process:0x2:sns_sig_t_2:0x48:sns_registry_se'
qcom_q6v5_pas 2400000.remoteproc: fatal error received: err_qdi.c:1233:EF:sensor_process:0x2:sns_sig_t_2:0x48:sns_registry_sensor.c:325
remoteproc remoteproc0: handling crash #22 in slpi
```

Each recovery was clean, 31 in a row, and stopping the daemon stopped them.

## Readings

With the port's patched `hexagonrpcd` (0.5.0_git20260824, built from
`pmaports-overlay/temp/`), the 65 stock config files, `sns_reg.conf` with the
revision line pointed at `socinfo/ssc_hw_rev`, a `socinfo/` of `soc_id` 457,
`hw_platform` MTP and `ssc_hw_rev` 5, and a registry generated by
`sscregistrygen` (130 files, no factory calibration), the hub came up without
a crash, wrote `sns_reg_version` and grew the registry to 131 files.

`ssccli`, tablet standing in landscape, leaning back, room light:

| Sensor | Reading |
|---|---|
| accelerometer | X 8.89, Y -0.05, Z 3.96 m/s² |
| light | 13 lux |
| magnetometer | X -89, Y 180, Z -225 µT, uncalibrated |

`iio-sensor-proxy` 3.9 with the X800 mount matrix
(`ACCEL_MOUNT_MATRIX="0, 1, 0; -1, 0, 0; 0, 0, 1"` on `fastrpc-*`) reports
orientation normal, tilt tilted-up, light 12 lux and a compass heading of
318°. The raw frame is the X800's: +X is the camera edge up.

`gpio-keys` with the inherited description registers and reports the cover
switch open and the pen switch set. `ap_therm` reads 28.9 °C beside SoC zones
at 29-32 °C.

`wf_therm` read 57-63 °C with the inherited pin state, which put pm8350
`gpio1` in high impedance. The stock X900 state (`gpio2_adc_default`) names
`gpio2`. With that pad in high impedance the channel reads 31.1-31.9 °C.
Stock converts both channels with its own tables rather than the generic
100 kΩ NTC curve, so a few degrees of difference from Android remain
possible.

## Not done

- The hall switches changing state are unchecked. Rotation was checked
  later the same day: `monitor-sensor` reported left-up and back to normal as
  the owner turned the tablet, and Plasma rotates the desktop to match in
  both directions. Volume-up, volume-down and power registered presses.
- The config files came from the firmware package on the host. The
  compressed ones needed `dump.f2fs`; Docker's kernel mounts the F2FS image
  but cannot read LZ4-compressed files.
- This unit's factory calibration lives in the `persist` partition on UFS,
  which was not read. The firmware package's `persist.img` is empty.
- The patched daemon answers the hub's `ro.revision` query from a table
  that says 4, the X800 unit's value. This tablet is revision 5. Both pick
  the same magnetometer config, but the value should come from the device.
- The second light sensor has not been told apart from the first.
- The X900 device package carries none of this: no daemon dependency, udev
  rules, mount matrix or extractor. The tree above was built with a local
  copy of the X800 extractor in its `--sensors-from` mode.
